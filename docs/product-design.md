# ScriptForge 产品设计

## 1. 产品目标

ScriptForge 的目标是帮助小说作者把已有小说章节快速转换为可继续打磨的剧本初稿。它解决的不是“AI 替作者创作完整成品”的问题，而是帮助作者完成最费力、最混乱的第一轮剧本化拆解。

黑客马拉松版本需要形成一个完整闭环：

```text
输入 3 章以上小说 → Source Facts → Dramatic Plan → Scene Cards → Dense Beats → ScriptForgeDocument 1.1 → Schema/引用/质量校验 → 可视化预览 → 导出 YAML
```

## 2. 目标用户

### 网络小说作者

他们已经有故事和角色，但缺少剧本化经验。ScriptForge 可以帮助他们快速看到作品改编成短剧、影视剧、广播剧或舞台剧的可能形态。

### 独立编剧与内容团队

他们需要快速评估一个小说 IP 是否适合改编。ScriptForge 能将长文本拆成场景、冲突、人物行动和对白，降低前期拆稿成本。

### 编辑与制片人

他们关注的是故事是否具备改编价值。结构化输出可以帮助他们快速浏览人物、场景数量、冲突密度和改编风险。

## 3. 核心用户问题

小说和剧本的表达方式不同。小说依赖叙述、心理描写和作者视角；剧本依赖场景、动作、对白、冲突和节奏。

用户真正需要的是：

- 从章节中提取可改编的事件。
- 把心理描写转成可表演的动作和对白。
- 拆分场景并明确每场戏的目的。
- 保持人物、地点、时间线一致。
- 让 AI 结果可以被编辑、校验、导出和继续生产。

## 4. 产品原则

### 结构优先

第一版不要追求生成最漂亮的文学文本，而要保证结构完整、字段稳定、结果可被工具消费。

### 作者可控

AI 输出应该是初稿，不是最终稿。用户可以修改 YAML、调整场景、改写对白、重新校验。

### 可追溯

每个章节都应该抽取关键事实，每个场景和 beat 都应该引用这些事实，让用户知道 AI 的改编依据，而不是只知道它大致来自哪个章节。

### 可校验

生成结果必须经过 Schema 校验。格式错误、字段缺失、引用不合法都要尽早暴露。

### 演示清晰

黑客松 Demo 要避免复杂路径，重点展示从小说到结构化剧本的完整链路。

## 5. MVP 功能范围

### 必须实现

- 章节输入：至少 3 个章节，包含章节标题和正文。
- 示例载入：准备一组内置小说样例，避免现场粘贴失败。
- AI 分析：抽取人物、地点、事件、冲突、人物动机。
- AI 生成：抽取 Source Facts，形成戏剧计划与自然分场，生成 `ScriptForgeDocument 1.1`。
- YAML 输出：将结构化对象转换为 YAML。
- Schema 校验：展示通过或失败，并列出错误。
- 质量诊断：检查来源事实使用、场景转折、对白轮次、摘要化倾向和内容容量。
- 剧本预览：用更适合人读的形式展示场景、对白、动作。
- 导出：导出 YAML 和 Markdown。

### 应该实现

- 风格选择：短剧、电影剧本、舞台剧。
- 改编报告：列出章节数、人物数、场景数、主要冲突和建议人工打磨点。
- 自动修复：Schema 校验失败时尝试修复结构字段、类型和轻量引用错误。

### 暂不实现

- 多人协同编辑。
- 复杂权限系统。
- 长期数据库存储。
- 专业排版导出，如 Final Draft。
- 真正的分镜图生成。

## 6. 信息架构

主工作台建议由三部分组成。

### 左侧：输入区

- 项目标题
- 章节列表
- 章节正文输入
- 示例文本按钮
- 风格选择
- 生成按钮

### 中间：分析与结构区

- 当前流程状态
- 人物表
- 地点表
- 场景卡片
- 改编报告

### 右侧：输出区

- YAML 编辑器
- Schema 校验状态
- 剧本文本预览
- 导出按钮

## 7. 关键交互

### 载入示例

用户点击“载入示例”，系统填入至少 3 个章节。这样 Demo 不依赖用户现场准备素材。

### 生成剧本

用户点击“生成”，系统分阶段展示状态：

```text
正在抽取原文事实 → 正在规划戏剧动作 → 正在形成自然场面卡 → 正在生成动作/对白 beats → 正在校验 Schema 和引用 → 正在检查剧本质量
```

### 查看校验结果

校验通过时展示通过状态。校验失败时展示字段路径、错误原因和修复入口。

### 编辑后重新校验

用户修改 YAML 后可以重新校验，证明结果不是一次性的静态输出，而是可继续生产的资产。

## 8. 成功指标

黑客松版本可以用以下指标说明价值：

- 输入章节数：至少 3 章。
- 生成场景数：根据自然场景边界自动生成，不按硬编码数量拆分连续场景。
- Schema 校验通过率：目标为示例 Demo 100% 通过。
- 来源事实覆盖率：每个 scene 和主要 beat 都有 `source_refs`，且引用存在于章节 `key_facts`。
- 场景卡完整率：每个 scene 都有 objective、opposition、entry_state、turning_point、exit_state 和 visual_atmosphere。
- 剧本质量诊断通过率：示例路径不触发错误级容量、摘要化、静态场景或对白轮次诊断。
- 可编辑性：用户修改 YAML 后可以重新校验。
- 导出完整性：YAML 和 Markdown 可下载。

## 9. 差异化表达

普通 AI 写作工具给用户一段文本，ScriptForge 给用户一份结构化剧本资产。

这份资产可以被阅读、编辑、校验、导出、版本管理，也可以继续连接分镜、拍摄计划、协作编辑器等后续工具。
