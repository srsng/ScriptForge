# ScriptForge 产品故事

## 一句话定位

ScriptForge 不是替作者重写小说，而是把小说改编成剧本时最混乱的第一稿，变成可验证、可编辑、可追溯的结构化资产。

## 背景

很多小说作者已经拥有完整的故事、人物和世界观，但当他们想把作品改编成短剧、影视剧本、广播剧或互动内容时，往往会卡在第一步。

小说和剧本使用的是两套表达语言。小说可以依靠心理描写、旁白、长段叙事和作者视角推进；剧本必须拆成场景、人物、动作、对白、转场和节奏。作者面对的不只是格式转换，而是一次叙事媒介的翻译。

传统 AI 写作工具可以生成一段看起来像剧本的文本，但结果通常难以继续加工：结构不稳定、字段不统一、无法校验，也很难追踪每场戏来自原文的哪一章。这样的内容可以被阅读，却不容易进入真正的改编工作流。

ScriptForge 要解决的就是这个断层。

## 目标用户

ScriptForge 面向希望把小说作品改编成剧本初稿的人，包括：

- 网络小说作者
- 独立编剧
- 短剧内容团队
- IP 孵化团队
- 需要快速评估改编潜力的编辑或制片人

这些用户共同的问题不是缺少故事，而是缺少一个低门槛、高效率、能继续编辑的剧本化起点。

## 产品故事

一个小说作者写完了三章都市悬疑小说，想把它改成短剧试水。

过去，他需要先手动拆稿：找出每章的主要冲突，判断能拆成几场戏，把心理描写改成可表演的动作和对白，维护人物关系和时间线，还要反复整理格式，才能得到一份可以继续打磨的剧本初稿。

使用 ScriptForge 后，他上传至少 3 个章节的小说文本。系统会先理解章节内容，再生成符合 YAML Schema 的结构化剧本。剧本中包含故事元信息、人物表、场景列表、动作、对白、旁白建议、转场、改编备注和来源引用。

作者拿到的不是一次性生成的最终稿，而是一份已经拆好结构的初稿。他可以直接修改对白、调整场景顺序、合并人物、删除旁白，也可以把 YAML 导入后续编辑器、校验器或分镜工具。

这让作者从面对空白剧本文档，变成在一份可编辑的剧本骨架上继续创作。

## 核心价值

### 降低改编门槛

ScriptForge 把小说到剧本的第一轮拆解自动化，让没有专业编剧经验的作者也能快速获得可用初稿。

### 提升创作效率

系统自动整理人物、场景、对白和动作，减少重复性的拆稿、格式化和结构整理工作。

### 保留作者控制权

ScriptForge 不把 AI 结果包装成不可修改的最终答案，而是输出清晰、透明、可编辑的 YAML，让作者继续掌控改编方向。

### 支持后续工作流

结构化 YAML 可以被校验、导出、版本管理，也可以继续连接剧本编辑器、分镜工具、拍摄计划和团队协作流程。

## 为什么强调 YAML

ScriptForge 的重点不是让 AI 写出一段剧本文本，而是让 AI 生成的内容能够被继续使用。

YAML 对人类友好，作者可以直接阅读和修改；Schema 可以校验字段完整性，避免 AI 漏掉场景、角色、时间、地点等关键内容；结构化字段也让后续工具可以稳定消费剧本数据。

因此，YAML 不是单纯的输出格式，而是 ScriptForge 把 AI 生成结果变成生产资产的核心设计。

## Demo 叙事

在黑客马拉松演示中，ScriptForge 可以用一组清晰的闭环展示价值：

1. 上传 3 个以上章节的小说文本。
2. AI 分析章节、人物、事件和叙事节奏。
3. 自动生成符合 Schema 的剧本 YAML。
4. 展示 YAML 校验结果。
5. 在预览区查看结构化剧本初稿。
6. 通过来源引用追踪场景对应的原始章节。
7. 修改字段后重新校验，证明结果可编辑、可继续生产。

这条演示路径能清楚地区分 ScriptForge 和普通聊天式生成器：它不是只生成文本，而是在构建一套 AI 辅助剧本改编工作流。

## 路演表述

小说作者缺的不是灵感，而是把小说翻译成剧本语言的第一步。

ScriptForge 让作者上传 3 个以上章节，自动生成符合 YAML Schema 的结构化剧本初稿。它拆出场景、人物、对白、动作和来源引用，让 AI 生成结果从一段文本变成可编辑、可验证、可继续生产的剧本资产。

我们希望降低小说影视化、短剧化、广播剧化的第一道门槛，让作者更快看到自己作品的另一种形态。
