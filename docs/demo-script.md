# ScriptForge 演示脚本

## 1. 演示目标

演示要让评委在最短时间内理解：ScriptForge 不是普通 AI 写作工具，而是一个把小说改编为结构化剧本资产的工作台。

必须覆盖题目要求：

- 输入 3 个章节以上的小说文本。
- 自动转换为结构化剧本。
- 输出 YAML 格式。
- 有 YAML Schema。
- 说明 Schema 的设计原因。

## 2. 30 秒开场

可以这样说：

> 很多小说作者已经有故事，但当他们想把小说改成短剧或影视剧本时，第一步非常痛苦：要拆场景、提炼冲突、改写对白、维护人物和地点，还要整理格式。ScriptForge 要解决的就是这个第一稿问题。它把 3 个章节以上的小说输入，转换成符合 YAML Schema 的结构化剧本初稿，让 AI 生成结果可以被校验、编辑、追溯和导出。

## 3. 3 分钟 Demo 路径

### 第一步：展示章节输入

操作：

1. 打开 ScriptForge 工作台。
2. 点击“载入示例”。
3. 展示左侧出现 3 个章节标题和正文。

讲解：

> 这里我们载入一段三章小说样例。题目要求至少 3 个章节，所以我们的输入从一开始就是章节化的，而不是一段普通长文本。

### 第二步：选择改编目标

操作：

1. 选择“短剧”。
2. 设置目标时长，例如 12 分钟。
3. 点击“生成剧本”。

讲解：

> 小说改编不是简单改格式。短剧、电影和舞台剧对场景密度、对白比例和节奏要求不同，所以我们把改编目标作为 metadata 写入结构中。

### 第三步：展示 AI 分析过程

操作：

1. 展示流程状态：原文事实抽取、戏剧计划、自然场面卡、密集 beats 生成、Schema/引用校验和质量诊断。
2. 展示人物表、地点表和主要冲突。

讲解：

> 我们不会让模型直接吐 YAML。生成请求里显式分出 Analyzer、Planner、Screenwriter 和 Reporter 的职责，要求它先抽取原文事实，再决定自然场景边界，最后输出符合 Schema 的 JSON。程序随后做 Schema、引用和质量校验，再转换成 YAML。

### 第四步：展示 YAML 输出

操作：

1. 切到 YAML 编辑器。
2. 展示 `script`、`metadata`、`source`、`characters`、`locations`、`scenes`。
3. 指出某个章节的 `key_facts`，再指出某个 scene 和 beat 的 `source_refs`。

讲解：

> 1.1 版本把追溯拆得更细：章节里先列出可改编事实，每场戏和每个 beat 再引用具体事实。作者看到的不只是“来自第几章”，还能判断这句对白、这个转折或这个动作到底改写了哪条原文依据。

### 第五步：展示 Schema 校验

操作：

1. 点击“校验”。
2. 展示校验通过状态。
3. 可选：删除一个必填字段，再展示错误路径。

讲解：

> YAML 是给作者和后续工具使用的，所以我们定义了 Schema。它会检查必填字段、字段类型、beat 类型和数组长度。跨引用关系，比如角色 ID 是否存在，会在应用层继续校验。

### 第六步：展示预览和导出

操作：

1. 切换到剧本预览。
2. 展示场景卡片和对白。
3. 点击导出 YAML 或 Markdown。

讲解：

> 作者拿到的不是最终稿，而是一份已经拆好结构、可以继续编辑的剧本初稿。它可以导出，也可以继续接入分镜、拍摄计划或协作工具。

## 4. 1 分钟精简版讲法

> ScriptForge 是一个 AI 小说转剧本工作台。用户输入至少 3 个章节，系统先抽取可引用的原文事实，再形成戏剧计划、自然场面卡和密集动作/对白 beats，最后输出符合 YAML Schema 的 `ScriptForgeDocument 1.1`。每场戏都有 scene card、来源事实、地点、人物、戏剧目的、冲突和 beats。我们还提供 Schema 校验、引用校验、质量诊断、剧本预览和 YAML 导出，让 AI 结果从一段文本变成可编辑、可验证、可继续生产的剧本资产。

## 5. 5 分钟完整版结构

1. 痛点：小说到剧本不是格式转换，而是媒介改编。
2. 方案：ScriptForge 提供结构化改编工作台。
3. 输入：至少 3 个章节。
4. 管线：Source Facts → Dramatic Plan → Scene Cards → Dense Beats → Document 1.1 → YAML。
5. Schema：保证结构完整和工具可消费。
6. 预览：人物、地点、场景、对白、改编报告。
7. 可追溯：章节提供 key_facts，scene 和 beat 关联 source_refs。
8. 可编辑：修改 YAML 后重新校验。
9. 可扩展：后续可连接分镜、拍摄计划、专业剧本格式。

## 6. 评委可能问题与回答

### 问：为什么不用 AI 直接输出 YAML？

答：YAML 对人类友好，但模型直接生成 YAML 容易出现缩进和格式错误。我们让模型输出 JSON，先用 Schema 校验，再由程序转换为 YAML，这样稳定性更高，尤其适合现场 Demo 和后续生产工具。

### 问：这和普通 AI 写作有什么区别？

答：普通 AI 写作输出的是一段文本；ScriptForge 输出的是结构化剧本资产。它包含人物表、地点表、场景、scene card、对白、动作、来源事实和改编报告，可以校验、编辑、导出和继续接入后续工具。

### 问：如何保证没有乱改原文？

答：每个章节都有 `key_facts`，每个场景和 beat 都有 `source_refs` 指向这些事实。`source_chapters` 只负责章节级索引，真正用于解释改写依据的是事实引用。改编报告还会说明压缩、合并或省略了哪些内容。

### 问：Schema 为什么这样设计？

答：剧本的核心单位是场景，所以 Schema 围绕 scene 设计。每个 scene 包含时间、地点、人物、scene card、戏剧目的、冲突和 beats。人物、地点、章节事实独立成表，是为了保持一致性和支持跨引用校验。

### 问：如果模型生成错误怎么办？

答：系统先做 Schema、引用和质量校验，失败后显示错误路径与诊断。修复器只处理结构字段、类型和轻量引用问题，不重新创作故事；如果生成链路失败，工作台保留输入和最近有效结果，并显示可读错误。

## 7. 收尾话术

> ScriptForge 的核心价值，是把 AI 生成从“看起来像剧本的一段文本”升级为“可生产的结构化剧本初稿”。它降低了小说作者进入短剧化、影视化和广播剧化改编的第一道门槛，也为后续分镜、拍摄计划和协作编辑留下了清晰接口。
